# Tool 调试参数录入区第一阶段优化方案

## 文档状态

| 项目 | 内容 |
|---|---|
| 状态 | Phase 1 已实施并通过完整门禁 |
| 适用版本 | 当前 1.x，兼容 2.0.0 UI Foundation |

| 适用范围 | Tool 调试页的 Form / Raw JSON 参数录入区 |

## 1. 目标

在不改变 Tool 参数数据、Schema 校验、脚本流水线和调用语义的前提下，提高参数录入区的扫描效率、错误定位效率和复杂 JSON 参数的编辑体验。

第一阶段重点解决：

1. 参数名、描述、默认值和约束的层级不够清晰。
2. 参数较多时难以快速找到必填、已填写和错误字段。
3. 执行被阻止时，缺少集中、可定位的原因说明。
4. 长描述占用过多垂直空间。
5. object / array 参数只有基础文本编辑能力，缺少格式化、复制和放大入口。

## 2. 非目标

第一阶段不实施以下内容：

- 不修改 `Skip` 的业务逻辑、默认值或请求序列化结果。
- 不改变 Form 与 Raw JSON 的 canonical arguments 同步机制。
- 不改变前置脚本启用后的必填参数延迟校验规则。
- 不增加或修改服务端 API、SQLite 数据表、导入导出格式。
- 不实现 object、array、`oneOf`、`anyOf` 的完整可视化结构编辑器。
- 不改变 Tool Schema 字段顺序。
- 不引入新的 UI 框架、图标库或设计系统。

## 3. 已确认决策

### 3.1 Skip

`Skip` 的现有语义保持不变：

- 选中时，该可选参数不进入最终 arguments。
- 取消选中时，该参数进入 arguments，并使用当前值、默认值或现有初始化规则。
- 必填参数继续不提供 `Skip`。
- 历史恢复、Form / Raw 切换和脚本执行继续使用相同 arguments 结果。

仅优化 `Skip` 的位置和视觉表达：

- 保留在字段标题行右侧，与字段名属于同一操作层级。
- 扩大可点击区域，文字与控件垂直居中。
- 使用现有 Checkbox 和主题 token，保证浅色、深色可见。
- disabled、focus-visible、hover 和 checked 状态必须清晰。
- 不把 `Skip` 改造成含义相反的“传递参数”开关，避免改变用户已有认知。

## 5. 交互设计

### 5.1 固定工具栏

保持现有参数收起、Form / Raw JSON、执行、保存请求和复制参数能力，增加紧凑的参数状态摘要：

- `必填 4/6`
- `错误 2`
- 没有错误时不显示错误数量。
- 点击错误数量，将焦点移动到第一个可编辑错误字段。
- 执行按钮 disabled 时，通过 Tooltip 解释首要阻塞原因，例如“还有 2 个必填参数未填写”。

### 5.2 参数筛选

当字段数量达到适合筛选的阈值时显示：

- 全部
- 必填
- 已填写
- 有错误

约束：

- 默认选择“全部”。
- 筛选只影响显示，不修改 arguments。
- 当前聚焦字段不能因一次异步保存被意外隐藏。
- Tool Tab 切换后，各 Tab 的筛选状态相互隔离。

### 5.3 字段信息层级

字段按以下顺序显示：

1. 字段名、必填星号和 `Skip`。
2. 描述。
3. 类型、默认值和约束摘要。
4. 输入控件。
5. 校验错误。

规则：

- 参数名继续使用等宽字体。
- 必填只显示红色 `*`，不追加“（必填）”。
- 描述默认最多显示两行；超出时提供“展开说明 / 收起说明”。
- 约束转换为紧凑、可读的摘要，例如 `string`、`1–64`、`≥ 0`、`pattern`。
- 完整 pattern 和较长约束可以通过 Tooltip 或展开区查看。
- 错误只在字段被编辑、失焦或尝试执行后显示，避免初次打开满屏红色。

### 5.4 字段布局

- 普通 string、number、integer、boolean、enum 字段保持两列。
- object、array、复杂组合字段独占一行并撑满参数内容区。
- 普通输入框保持合理阅读宽度，不在超宽屏无限拉伸。
- 复杂 JSON 编辑区撑满内容宽度。
- 760px 以下切换为单列，不产生水平滚动。

### 5.5 复杂 JSON 参数

第一阶段继续使用 JSON 文本编辑，但增加：

- 格式化
- 复制 JSON
- 放大编辑
- JSON 类型和条目数摘要，例如 `Array<Object> · 3 项`
- 合法性状态和靠近编辑器的错误信息

放大编辑复用现有 JSON 大弹层和 Viewer 视觉规范，不创建第二套弹层或 JSON 组件。

### 5.6 校验与执行

- Form 和 Raw JSON 继续使用同一份 canonical arguments。
- 筛选、展开说明和放大编辑不得改变参数值。
- 前置脚本启用时，required 问题继续延迟到脚本执行后校验。
- 非 required 类型、格式和范围错误仍阻止执行。
- 点击执行且存在错误时，保留当前输入并聚焦第一个错误字段。
- 不重复使用顶部错误文本、Toast 和字段错误播报同一问题。

继续复用：

- `ParameterControls.tsx` 中的 Switch、Radio、Select。
- 现有 Form / Raw JSON 同步方法。
- 现有 JSON Viewer、放大弹层、Toast 和 Phosphor Icons。
- `redesign.css` 中的语义 token；后续按 2.0.0 规划渐进迁移样式，不在本次重写全部 CSS。

## 7. 状态与身份边界

- 参数值、输入模式、子树草稿继续绑定 `tabId`。
- 参数筛选、描述展开和错误定位状态也必须按 `tabId` 隔离。
- Tool、Server 或项目切换后，旧异步结果不得写入当前 Tab。
- 保存失败必须保留当前草稿、筛选和滚动位置。
- 历史 Run 恢复只恢复请求和响应，不伪装为新的执行结果。

## 8. 可访问性

- 筛选使用 SegmentedControl 或具有等价语义的按钮组。
- 错误摘要使用可聚焦按钮，支持 Enter / Space。
- 点击错误摘要后聚焦真实输入控件，并通过 `aria-describedby` 读取错误。
- `Skip` 保留 Checkbox 语义和可访问名称。
- 复杂 JSON 操作按钮提供明确的 `aria-label`。
- Tooltip 不能作为获取必要错误信息的唯一方式。
- 任何按钮操作都不得提交外层表单或改变页面滚动位置。

## 9. 测试方案

### 9.1 单元与组件测试

- 参数数量、必填完成数量和错误数量计算正确。
- 全部、必填、已填写、有错误筛选正确且不改变 arguments。
- 点击错误摘要聚焦第一个错误字段。
- `Skip` 语义与修改前完全一致。
- Form / Raw JSON 双向同步不回归。
- 复杂 JSON 格式化、复制、放大和非法 JSON 状态。
- 前置脚本启用后的 required 延迟校验不回归。
- Tool Tab 切换后筛选、草稿和错误状态不串 Tab。
- 浅色、深色只依赖 token，不写主题专属业务逻辑。

### 9.2 浏览器验证

- 1024px、1440px 和超宽桌面布局。
- 长描述、长字段名、50 个以上字段和大型 JSON。
- 键盘完成 Form / Raw 切换、筛选、输入、Skip 和执行。
- 点击 Radio、Checkbox、Select、筛选和错误摘要不发生滚动跳跃。
- 参数收起后结果区自然上移，展开后恢复 Split Pane。

### 9.3 合并门槛

实施完成后必须通过：

```bash
npm run typecheck
npm run test
npm run build
```

若修改 Split Pane、核心参数状态或生产用户旅程，则运行：

```bash
npm run verify
```

## 10. 实施顺序

1. 为参数摘要、筛选和 `Skip` 现有语义补 RED 测试。
2. 提取纯计算函数：字段状态、筛选和约束摘要。
3. 实现工具栏摘要和筛选，不改字段数据流。
4. 优化字段层级、长描述和 `Skip` 布局。
5. 增加复杂 JSON 格式化、复制和放大编辑。
6. 补键盘、焦点、滚动和 Tab 身份隔离测试。
7. 运行完整质量门槛并做浅色、深色浏览器验收。

## 11. 验收标准

- 用户可以在长表单中快速识别必填、已填写和错误字段。
- 执行被阻止时，可以看到原因并直接定位到对应参数。
- `Skip` 的请求行为与当前版本完全一致。
- 普通字段两列、复杂字段整行的布局稳定。
- 长描述默认不挤占大量响应空间。
- 复杂 JSON 可以格式化、复制和放大编辑。
- Form / Raw JSON、脚本校验、历史恢复和自动保存没有行为回归。
- 浅色、深色和键盘操作均满足前端开发规范。

## 12. 后续阶段

第二阶段单独设计并确认：

- `array<object>` 条目式增删、排序和折叠编辑。
- object 嵌套字段组。
- discriminator 驱动的 `oneOf` / `anyOf` 分支选择。
- 复杂字段局部 Form / Raw 双模式。

第二阶段涉及 Schema 解释和参数状态模型，不纳入本方案的第一阶段实现范围。
