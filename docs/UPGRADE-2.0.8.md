## 1. 目标与非目标

### 目标

1. 断言结果始终并列展示期望值与实际值；无法取得实际值时显示明确空值，占位不应与 JSON `null` 或脱敏值混淆。
2. 场景配置使用与基本信息相同的 Disclosure 栏目。新建时默认展开，打开已有场景或首次保存成功后默认收起，用户可随时切换。
3. 场景执行结果使用左侧执行流程、右侧步骤详情的主从布局。全部步骤始终可见，详情默认未选择且收起。
4. 步骤详情同时展示解析后的输入参数、响应结果与该步骤断言；场景级断言作为末尾独立流程节点。
5. 执行结果与执行历史改为上下排列的同级 Disclosure 栏目。执行历史按钮直接展开历史栏目；历史记录按当前测试用例隔离，并复用执行结果正文。

### 非目标

- 不改变场景运行、重试、轮询、清理步骤或断言求值语义。
- 不复制 Run 响应到测试表，不改变现有 SQLite 表结构。
- 不修改测试报告的基线更新规则，不增加新的前端依赖。
- 不在本版本增加执行结果比较、删除历史或历史搜索。

## 2. 用户流程与交互状态

- 新建场景：基本信息和场景配置均展开；场景配置包含场景输入、失败策略、步骤编排及引用检查。
- 编辑已有场景：基本信息和场景配置默认收起；展开状态是当前编辑器的本地 UI 状态。
- 首次保存成功：草稿获得持久化 ID，场景配置收起；保存失败则保持当前展开状态和草稿。
- 执行场景：执行结果栏目默认收起；开始一次新执行后自动展开。步骤详情不自动展开。
- 查看结果：点击左侧步骤，在右侧显示详情；再次点击当前步骤收起详情；选择其他步骤时仅切换一个详情。
- 查看历史：执行历史栏目位于执行结果下方并默认收起；点击编辑器的“执行历史”按钮或栏目标题后展开并加载当前用例的分页历史。选择记录后使用相同结果正文展示，不嵌套第二层结果栏目。
- 切换用例、项目或执行记录：清除步骤选择和不属于新身份的响应数据，旧异步响应不得写入新上下文。

## 3. API 与数据契约

- 扩展现有 `GET /api/projects/:projectId/test-executions`，新增可选 `testCaseId` 查询参数。
- `testCaseId` 必须是 UUID，并在 Repository 查询中与 `projectId` 同时过滤。
- 分页游标绑定 `projectId + testCaseId` 筛选上下文；不得跨用例复用游标。
- 响应继续使用现有 `TestExecutionReportPage`，属于向后兼容的查询能力扩展。
- 历史详情继续通过现有 execution ID 与 Run ID 获取，并校验 project、execution 和 run 身份。

## 4. UI、可访问性与响应式

- 执行结果外层复用共享 Disclosure，样式层级与基本信息一致。
- 执行结果和执行历史可以独立展开；收起后不保留内容高度。
- 两个栏目的正文延伸至 Disclosure 外层边界，不增加内嵌卡片边距或重复边框。
- 桌面端结果主体为约 260px 的流程栏和自适应详情栏；低于 760px 改为上下排列。
- 流程项使用原生 button，提供可见焦点、`aria-current` 与详情关联；状态同时使用图标和文字。
- 结果/历史使用原生 button 驱动的共享 Disclosure，通过 `aria-expanded` 与 `aria-controls` 表达状态，并支持 Enter 和 Space。
- 右侧空态、响应加载失败、无 Run、无断言和步骤错误均有双语说明。
- feature CSS 只使用现有语义 token，不引入新色值、阴影或第二套组件样式。

## 5. 代码结构与风格

- `ScenarioTestCaseEditor` 只负责场景草稿与场景配置 Disclosure。
- `TestExecutionPanel` 保留共享执行概要与单 Tool 结果，并将场景结果委托给聚焦的场景结果组件。
- 断言值展示提取为共享组件，确保单 Tool、场景步骤、场景级断言和历史详情语义一致。
- 使用稳定 execution/step/assertion ID 作为 key 和选择身份，不使用列表 index 代替持久化身份。

测试必须覆盖：实际值缺失、`null` 与脱敏区分；场景配置新建/编辑/保存失败状态；结果与历史默认收起及新执行自动展开；步骤默认未选择与切换/收起；每步参数、响应和断言隔离；场景级断言；历史用例筛选、分页身份、Disclosure 键盘操作和无嵌套历史详情复用。

## 7. 边界、发布与回滚

- 始终：保持 project、testCase、execution、step、run 身份隔离；双语同步；先写失败测试。
- 需确认：数据库迁移、改变断言求值或 Run 持久化语义、增加依赖。本次均不需要。
- 禁止：把 secret 写入 URL 以外的现有受控筛选参数之外的位置、Toast、日志或浏览器存储；使用未校验的 API 数据渲染。
- 发布条件：聚焦测试与 `npm run verify` 全部通过；浅色/深色和窄屏布局无双滚动或遮挡。
- 回滚：本次无 migration；可整体回退前端组件与可选查询参数，旧客户端不受新增参数影响。

## 8. 验收标准

- 用户不展开任何步骤详情也能看到完整执行流程与每步状态。
- 任意时刻最多一个流程节点显示详情；新执行或切换历史记录后详情恢复未选择状态。
- 每个步骤详情只显示属于该 `stepRecordId` 的断言与属于该 `runId` 的响应。
- 无法取得实际值时仍显示“实际值”和空占位；JSON `null` 显示为 `null`；脱敏值显示“已脱敏”。
- 历史按钮可直接展开“执行历史”栏目，历史列表只包含当前测试用例，选择记录后展示与最新结果一致且无重复外框的主从界面。
