## 1. 更新摘要

2.0.2 解决三个直接影响操作效率的问题：Tools 侧栏底部控件与本地服务版本信息互相覆盖；Tools 主 Raw JSON 参数输入框默认高度过大；环境变量、自动化测试、测试套件、测试报告和运行历史缺少完整的模块级使用说明。

本版本必须交付：

1. 重构侧栏 footer 的布局所有权，使服务状态、语言、主题和侧栏收起操作在所有支持宽度下互不遮挡。
2. 将 Tools 主 Raw JSON 参数输入框的默认高度从当前 260px 降低到紧凑尺寸，同时保留用户手动扩大能力。
3. 新增共享 `ModuleHelpPopover`，在五个一级模块标题后显示 `?`，点击后展示“模块用途、如何配置、如何使用、产生效果”。
4. 为新说明补齐 `zh-CN/en-US`、键盘、焦点、响应式和页面回归测试。

## 2. 目标与非目标

### 2.1 目标

- “本地服务 v…”始终可读或能通过紧凑状态入口获取，不再被语言/主题/收起控件覆盖。
- 所有侧栏底部操作在 176px 展开侧栏、64/56px 紧凑侧栏和手动完全收起状态下均可访问。
- Raw JSON 模式默认展示足够的编辑行数，但不再挤占大部分请求面板。
- 五个模块使用同一个帮助组件和同一套信息结构，不在 Feature 中复制 Popover/focus 逻辑。
- 新用户能从当前页面理解模块的配置入口、操作步骤、结果和关键安全边界。

### 2.2 非目标

- 不重新设计一级导航、品牌区、Server Tabs 或 Tools Catalog。
- 不改变侧栏收起状态的存储方式和页面路由状态。
- 不缩小脚本编辑器、字段级 JSON 编辑器、JSON 放大 Dialog 或只读结果 Viewer。
- 不新增 Markdown/HTML 远程帮助内容、文档服务或联网加载。
- 不把帮助内容写入数据库、项目导出、Run、测试定义或浏览器业务状态。
- 不借说明文案改变实际执行、环境变量解析、测试套件调度、报告或回放语义。

## 3. Tools 侧栏 footer 冲突修复

### 3.1 现状与根因

当前展开侧栏宽度为 176px。`workbench-sidebar__footer` 使用单行 flex，同时放置：

- “本地服务 v{{version}}”状态；
- 88px 语言 Select；
- 32px 主题按钮；
- 32px 收起按钮；
- 控件间距和左右 padding。

这些内容的最小总宽度明显超过 176px；`service-indicator` 虽然允许收缩，但内部版本文本没有可靠的溢出契约，因此发生覆盖。900px 以下侧栏缩为 64px/56px 后，完整语言 Select 仍可能进入 controls，冲突更明显。

### 3.2 展开侧栏布局

展开侧栏 footer 改为两行 grid，不再让服务状态与操作争抢一行：

```text
┌────────────────────────┐
│ ● 本地服务 v2.0.0      │
│ [简体中文⌄] [主题] [收起] │
└────────────────────────┘
```

要求：

- 第一行只显示服务状态；文本使用单行省略，完整内容通过 Tooltip 和可访问名称获取。
- 第二行是 `.sidebar-controls`；语言选择占剩余宽度，主题与收起按钮保持 32×32。
- footer 使用内容驱动高度，不通过绝对定位叠放；导航区设置 `min-height: 0` 并成为空间不足时的唯一滚动区域。
- 服务状态点、主题和语言状态不得只靠颜色或图标表达。
- 中文、英文和更长版本号（例如 prerelease/build metadata）都不得覆盖或推动按钮出界。

### 3.3 紧凑与完全收起状态

当响应式侧栏变为 64px/56px 图标轨道时：

- 服务状态只显示状态点，Tooltip/`aria-label` 仍包含完整“本地服务 v{{version}}”。
- `LanguageSwitcher` 使用显式 `compact` 变体，以 Phosphor `Translate` 图标作为 32×32 触发器；点击后在 Popover 中选择“简体中文 / English”。
- 主题和收起按钮继续使用图标按钮，垂直排列并保持至少 4px 间距。
- 紧凑语言入口与展开 Select 共用同一个 locale 解析、切换、Cookie/localStorage 和 `aria-live` 通知逻辑，不能维护第二套语言状态。
- 手动完全收起后，侧栏 footer 与其他侧栏内容一起不可见，只保留现有舞台上的恢复按钮。

### 3.4 状态与兼容

- 语言切换不得重置 project、connection、Tool Tab、参数草稿、Run、滚动位置或侧栏状态。
- 主题切换不得改变布局尺寸或导致 footer 跳动。
- 收起/展开只改变布局，不卸载当前页面或关闭已打开的帮助 Popover之外的业务 Dialog。
- 继续使用现有 `workbench.localService`、主题和收起国际化语义；新增紧凑入口文案必须同步加入两种语言。

## 4. Tools Raw JSON 输入框高度

### 4.1 现状与范围

主参数 Raw JSON 输入框是 `ParameterEditor` 中 `.raw-arguments-panel > textarea`。旧 `app.css` 为它设置 220px，后加载的 `redesign.css` 又覆盖为 260px，因此默认占用过多请求面板空间。

2.0.2 只调整完整 Tool 参数的 Raw JSON 输入框，不影响：

- object/array 字段级 JSON 编辑器；
- JSON 放大编辑 Dialog；
- before/after 脚本编辑器；
- 场景输入、断言 expected 和对比规则；
- 请求结果与只读 JSON Viewer。

### 4.2 新尺寸契约

- 默认高度：160px，约比当前 260px 减少 38%。
- 最小手动调整高度：120px，避免控件缩到无法编辑。
- 最大手动调整高度：`50dvh`，避免覆盖整个工作区或制造不可达操作。
- 保留 `resize: vertical`；用户需要查看较大 JSON 时可以向下拖动，放大编辑仍走现有 Dialog。
- 760px 以下默认高度可以降到 140px，但最小高度仍不得低于 120px。
- 输入框本身滚动 JSON 文本；调整高度不得改变 request/result Split Pane 的滚动所有权。

### 4.3 CSS 所有权

- 删除或收敛 `app.css` 与 `redesign.css` 对该选择器互相覆盖的高度声明，只保留一个权威组件样式来源。
- 继续使用现有边框、字体、主题 token、invalid 和 focus-visible 状态。
- 不使用 `!important` 或更高 specificity 掩盖旧规则。
- 切换 Form/Raw、Tool Tab、主题或语言不得修改 canonical arguments 或触发意外提交。

## 5. 共享模块帮助组件

### 5.1 放置位置

以下页面在左上角一级标题文字之后、说明文字之前增加 `?` 图标按钮：

1. 环境变量；
2. 自动化测试；
3. 测试套件；
4. 测试报告；
5. 运行历史。

标题结构统一为：

```text
[模块标题] [?]
[现有一句话说明]
```

`?` 与标题保持同一标题行，使用 28×28 紧凑 IconButton 和 Phosphor `Question`。它不能被放进右侧业务操作区，也不能替代页面现有的一句话说明。

### 5.2 `ModuleHelpPopover` 契约

新增共享组件建议放在 `src/client/components/overlays/ModuleHelpPopover.tsx`。Feature 只传入已国际化的展示内容：

```ts
interface ModuleHelpSection {
  id: "purpose" | "configure" | "use" | "effect";
  title: string;
  items: readonly string[];
}

interface ModuleHelpPopoverProps {
  moduleName: string;
  triggerLabel: string;
  summary: string;
  sections: readonly ModuleHelpSection[];
}
```

组件要求：

- 点击、Enter 或 Space 打开，触发器提供国际化 `aria-label`、`aria-expanded` 和 `aria-controls`。
- Popover 使用 `role="dialog"`、可访问标题和显式关闭按钮；打开后焦点进入说明区域或关闭按钮。
- Escape、关闭按钮和点击外部均可关闭；关闭后焦点返回原 `?` 按钮。
- 宽度建议 360–440px，并受视口限制；内容较长时只有 Popover body 滚动。
- 320px 视口下不能溢出屏幕；不得被 sticky header、Split Pane 或列表裁剪。
- 浅色和深色使用现有 overlay/token；不新增卡片墙、渐变、阴影体系或 Feature 私有 Popover。
- 帮助文本作为纯文本渲染，不执行 HTML；不展示 secret、连接凭证或当前业务数据。
- 每次只允许一个模块帮助 Popover 打开；切换一级页面时自动关闭，不持久化打开状态。

### 5.3 内容编写模板

每个模块的帮助内容严格使用四段，避免五个页面各写一套难以扫描的结构：

| 段落 | 回答的问题 |
|---|---|
| 模块用途 | 这个模块解决什么问题，管理的对象是什么 |
| 如何配置 | 需要选择或填写什么，作用域、身份和关键限制是什么 |
| 如何使用 | 用户从哪里开始，按什么顺序操作，在哪里查看结果 |
| 产生效果 | 保存或执行后发生什么，哪些数据会被影响，哪些不会 |

所有内容同时提供 `zh-CN/en-US`。Tool、Server、Run、ID、JSONPath、Header、Bearer Token、Profile 等稳定产品/协议词保持既有命名，不通过字符串拼接组成句子。

## 6. 五个模块的说明内容

### 6.1 环境变量

**模块用途**

- 集中管理连接认证、Tool 调用和脚本可复用的配置值。
- 区分项目变量、Server 变量与环境 Profile。

**如何配置**

- 选择项目或 Server 作用域，填写变量名称、文本/JSON 值并按需标记敏感值。
- Profile 可以继承另一个 Profile，并对项目或 Server 变量设置覆盖或“不设置”。
- 在连接预览中检查继承链、来源、缺失引用和最终解析结果；敏感值始终隐藏。

**如何使用**

- 在 Header、Bearer Token 等连接配置中使用 `{{VARIABLE_NAME}}` 引用。
- 脚本通过既有 `ctx.env` API 读取或按权限暂存写入；连接需要特定 Profile 时先激活它。

**产生效果**

- Server 同名变量覆盖项目变量，Profile 覆盖在解析时生效。
- 引用字符串被保存，实际 secret 不写入普通日志、Toast 或默认导出。
- 缺失或无效引用会在连接/执行前暴露，不静默替换为空值。

### 6.2 自动化测试

**模块用途**

- 将单 Tool 调用或多步骤场景保存为可重复执行的测试定义。
- 使用声明式断言验证响应、错误、HTTP 或其他受支持数据源。

**如何配置**

- 单 Tool 用例配置名称、Server、Tool、参数、断言、超时和启用状态。
- 场景用例配置顺序步骤、固定参数、输入/变量/前置步骤映射、响应提取、轮询和失败策略。
- 步骤只能引用位于它之前的步骤和变量，避免前向引用。

**如何使用**

- 新建并保存定义后执行；有未保存修改或已移除 Tool 时先修正再运行。
- 破坏性 Tool 必须显式确认；运行中可以取消，完成后查看步骤、断言和完整调用轨迹。

**产生效果**

- 每次执行保存不可变定义快照、最终参数、断言结果以及关联 Run/Workflow。
- 场景临时变量仅存在于本次执行，不写回项目或 Server 环境变量。
- 测试不创建隐藏 Tool Tab，也不绕过现有连接认证和运行状态机。

### 6.3 测试套件

**模块用途**

- 将多个单 Tool/场景用例组合为一次批量验证，并汇总结果。

**如何配置**

- 选择套件成员并保持稳定顺序，设置 `1–8` 有限并发和失败后是否停止调度。
- 含场景成员时，为本次套件执行填写所需输入；成员之间不共享临时变量。

**如何使用**

- 保存套件后执行，启动前检查 Server、Tool、环境变量和破坏性步骤。
- 运行中可以取消；完成后按配置顺序查看成员状态和详细报告。

**产生效果**

- 调度受并发上限约束，成员认证、输入、结果和 identity 相互隔离。
- “失败后停止”阻止尚未开始的成员继续调度，但不会伪造已运行成员的结果。
- 套件报告保留执行时成员快照，后续编辑或删除定义不会改写历史报告。

### 6.4 测试报告

**模块用途**

- 查看自动化测试执行历史、断言结果和关联 Run/Workflow 完整调用追溯。
- 管理测试定义的安全导入导出和显式基线更新。

**如何配置**

- 查看报告本身无需配置；导入时必须为导出包里的每个 Server 显式绑定当前项目 connection ID。
- 选择 ID 冲突策略：复制、跳过或覆盖并创建新 revision。

**如何使用**

- 从左侧选择一次执行，检查状态、步骤、断言、参数、响应和协议轨迹。
- 只在实际值可用且未被脱敏时显式确认更新基线。
- 使用“导出定义/导入定义”迁移测试定义；刷新重新读取当前项目报告列表。

**产生效果**

- 历史报告保持不可变；更新基线创建新的测试定义 revision，不重写原报告。
- 默认导出不含凭证、解析后的 secret、执行历史或报告。
- 导入在完整校验后原子写入；任何绑定或校验失败都不留下部分数据。

### 6.5 运行历史

**模块用途**

- 汇总项目内所有 Tool 调用，并回溯请求、响应、HTTP、RPC、时间线和 Tool 快照。

**如何配置**

- 使用 Tool 名称、connection ID、状态、来源、固定状态和时间范围筛选；应用后才查询，重置清空草稿和当前详情。
- 固定重要 Run 方便查找；项目对比忽略规则使用受限、安全的 JSONPath 子集。

**如何使用**

- 选择 Run 查看详情；可打开调试、创建测试用例、显式回放或对比直接来源。
- 回放前检查当前 Tool Schema 变化和副作用风险，按要求分别确认。

**产生效果**

- 历史 Run 不可变；打开调试只恢复内容，不会执行 Tool。
- 回放创建新的 Run，并始终使用来源 Run 的 connection ID 和原始参数以及当前 Tool 快照。
- 固定只影响查找/保留语义，不改变结果；对比只读取服务端已保存且可比较的数据。

## 7. 状态、身份与兼容

- 帮助 Popover 的打开状态属于页面瞬时 UI state，不进入 URL、localStorage、SQLite 或导出。
- 语言切换只替换展示资源，不能重建页面 Feature state 或改变当前选择。
- 帮助文案描述的行为必须与 2.0.0/2.0.1 已实现契约一致；发现不一致时先修正文档或单独立项，不能用文案伪造能力。
- 所有 Connection 场景继续以 connection ID 隔离，不能因帮助或布局调整按 URL/名称合并。
- JSON 高度调整只改变展示，不修改 raw draft、canonical arguments、校验错误或执行 payload。
- 本计划不新增 API、migration 或数据格式，因此 2.0.2 可以回滚前端产物而无需数据降级。

## 10. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| footer 高度增加挤压短视口导航 | 中 | 导航成为唯一弹性滚动区，footer 内容驱动且固定可达 |
| compact 语言入口形成第二套 locale 状态 | 高 | 展开与紧凑变体复用同一解析、切换和通知函数，只改变呈现 |
| 单纯提高 CSS specificity 留下双重高度来源 | 中 | 删除冲突声明并指定唯一组件样式所有者，不使用 `!important` |
| JSON 默认过矮影响大参数编辑 | 中 | 保留 120px 下限、垂直 resize 和既有放大编辑路径 |
| 五个页面复制帮助逻辑后行为漂移 | 高 | 共享 `ModuleHelpPopover`，Feature 只提供翻译后的内容 |
| 帮助文案与真实产品行为不一致 | 高 | 以共享 schema、现有测试和版本规范逐项复核；不确定能力不写成已交付事实 |
| 模块帮助与筛选帮助 Popover 冲突 | 中 | 统一 overlay 协调、Escape/外部关闭和一次只开一个的规则 |
