## 1. 目标与非目标

### 目标

1. 五个业务模块的帮助弹层包含页面描述，并使用统一、清晰的 Phosphor 信息图标。
2. 运行历史中的固定按钮拥有独立布局列，不遮挡成功或失败状态。
3. 自动化测试与测试套件的顶部操作按用户工作流重新排序。
4. 套件并发数支持 1–8 的手动数字输入，已添加成员支持拖拽排序并保留键盘排序路径。
5. 单 Tool 测试的基本信息可展开收起；新建时展开，编辑已有用例时默认收起；超时归入可扩展的“测试配置”模块。
6. Tool 调试视图按“调试、Tool 定义、已保存、脚本、执行历史”展示。

### 非目标

- 不改变测试执行、断言、套件调度或持久化契约。
- 不改变按钮文案（明确要求修改的“是否启用”和“执行历史”除外）。
- 不引入新的 UI、拖拽或图标依赖。
- 不改变项目、连接、Tab、Run 或套件成员的稳定身份。

## 2. 用户流程与状态

- 页面标题旁的信息按钮打开结构化说明，说明中首先展示页面原有描述，再展示用途、配置、使用和效果。
- 已有单 Tool 或场景用例打开后基本信息默认收起；新建用例时默认展开。用户可通过 Disclosure 按钮切换，键盘与指针行为等价。
- 套件并发数通过数字输入设置，客户端限制为规范定义的 1–8。
- 套件成员拖放只改变当前草稿的 `position`；保存后才写入服务端。上移/下移按钮作为键盘等价路径保留。
- 运行历史固定按钮与状态标签分列显示，固定操作仍不触发打开 Run。

## 3. 状态模型与身份边界

- 展开状态和拖拽源均为页面本地 UI 状态，不写入业务模型。
- 成员排序以稳定 `member.id` 定位，重排后只重新计算 `position`，不改变 `member.id` 或 `testCaseId`。
- 所有 API 请求继续携带原有 `projectId`、连接 ID、Tab ID、Run ID 与 revision。
- 本次无 Schema、API、SQLite migration、secret、导入导出或日志变化。

## 4. UI、键盘与可访问性

- 帮助入口继续使用 `button`、对话框语义、Escape 关闭与焦点恢复。
- 基本信息使用共享 `Disclosure`，暴露 `aria-expanded` 与 `aria-controls`。
- 拖拽成员提供可见拖拽把手、拖放目标反馈和上移/下移图标按钮；图标按钮均有国际化 `aria-label`。
- 颜色、间距、圆角、图标和控件只使用现有 token、Phosphor 与项目 primitives。

## 5. 验证与发布条件

- 组件测试覆盖帮助描述、图标契约、操作顺序、默认收起/展开、测试配置位置、并发数字输入、成员拖拽/键盘排序、固定按钮布局结构和 Tool 视图顺序。
- 运行聚焦 Vitest、`npm run typecheck`、`npm run test`、`npm run build`。
- 因涉及核心工作区布局与 Tool 视图，交付前运行 `npm run verify`。
- 任一门禁失败即停止发布；回滚仅涉及本次前端组件、样式、文案和测试，不涉及数据迁移。
