## 1. 目标

1. 请求参数、断言和执行结果统一使用与基本信息相同的 Disclosure 栏目层级。
2. 请求参数在新建用例时默认展开，打开已有用例或保存成功后默认收起。
3. 断言默认收起，并允许用户独立展开或收起。
4. “最近一次执行”统一更名为“执行结果”；默认收起，开始执行后自动展开。
5. 请求参数只保留栏目级展开入口，移除 Form 前重复的内部展开按钮。

## 2. 交互状态

- 新建单 Tool 用例：基本信息、测试配置、请求参数展开，断言与执行结果收起。
- 编辑已有用例：基本信息、测试配置、请求参数、断言与执行结果均默认收起。
- 保存成功：请求参数收起；保存失败时保留草稿及当前展开状态。
- 执行用例：服务端接受执行后，执行结果自动展开并持续展示进行中或终态信息。
- 切换用例、项目或创建新用例：执行结果恢复默认收起，旧执行数据不得进入新身份上下文。

## 3. UI 与可访问性

- 全部栏目复用共享 `Disclosure`，使用原生 button、`aria-expanded` 和 `aria-controls`。
- 栏目触发区的高度、间距、边框和展开图标与基本信息一致。
- 参数编辑器在 Tool 调试页继续保留内部展开按钮；仅在测试用例栏目内隐藏该重复入口。
- 收起内容不保留高度，展开内容直接衔接栏目边界，不增加嵌套外框。
- 中英文资源同步更新，不新增设计系统、依赖或硬编码颜色。

## 4. 非目标与边界

- 不改变测试定义、断言求值、Tool 调用或执行持久化语义。
- 不修改 API、SQLite schema、项目/连接/用例/执行身份隔离。
- 不改变场景测试现有的场景配置、执行结果和执行历史交互。

## 5. 验证

```bash
npx vitest run src/client/features/testing/__tests__/TestCasesPage.test.tsx
npm run typecheck
npm run verify
```

回归测试覆盖：栏目默认状态、手动展开、请求参数内部箭头移除、保存成功后收起、执行前结果收起、执行后结果自动展开，以及中英文名称。

验证结果：最新 Vitest `874/874`、类型检查与生产构建通过；最近一次完整验证的 Playwright `7/7` 通过。

## 6. 后续缺陷修复

- 场景配置、执行结果和执行历史之间统一只绘制一条相同的栏目分割线。
- 场景步骤调用失败时，从关联 Run 或工作流执行中保留安全错误码与说明，并在场景与步骤详情中同时展示；未知上游异常仍执行脱敏，不向界面泄露原始错误。
- 场景后续步骤因映射参数不符合目标 Tool Schema 而无法创建 Run 时，保留 `INVALID_ARGUMENTS` 及具体字段校验原因，不再降级为笼统的 `TEST_EXECUTION_FAILED`。
- 单 Tool 与场景测试的操作按钮统一简化为“保存”和“删除”，英文同步为 “Save” 和 “Delete”。
- 基本信息不再展示标签编辑项；既有定义中的标签数据仍保留，避免视觉调整破坏持久化兼容性。
- 自动化测试的“是否启用”控件保留标签与 Switch 语义，但不再在开关后重复显示“已启用 / 已停用”状态文字。
