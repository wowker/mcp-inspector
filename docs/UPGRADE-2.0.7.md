## 1. 目标与非目标

### 目标

1. 将原“测试目标”中的 Server 和 Tool 合并到“测试配置”。
2. 测试配置按 Server、Tool、超时时间（毫秒）的顺序展示。
3. 测试配置复用基本信息的 Disclosure 样式和交互。
4. 新建用例时测试配置默认展开，编辑已有用例时默认收起，并允许用户随时展开或收起。

### 非目标

- 不改变场景测试中每个步骤的 Server 和 Tool 配置方式。
- 不改变测试用例 API、持久化结构、执行逻辑、断言或超时语义。
- 不新增依赖、翻译文案、数据库迁移或身份边界。

## 2. 用户流程与状态

- 新建单 Tool 用例时，基本信息和测试配置同时展开，用户可依次选择 Server、Tool 并设置超时。
- 打开已有单 Tool 用例时，两个栏目默认收起，减少编辑器的初始占用空间。
- 栏目展开状态属于组件本地 UI 状态；切换到新建或已有用例时，根据 `draft.id` 重新初始化。
- 折叠栏目使用共享 Disclosure，具备 `aria-expanded`、`aria-controls` 以及 Enter/Space 键盘操作。

## 3. 数据、安全与兼容性

- Server、Tool 和超时继续写入原有 `ToolTestCaseDraft`，保存请求与服务端契约不变。
- Project、Connection、Tool、测试用例和 Run 的身份隔离不变。
- 本次不读取、复制或新增任何 secret，也不改变导入导出和日志内容。
- 场景测试的目标仍由稳定步骤 ID 管理，不受本次布局调整影响。

## 4. UI 与响应式

- 测试配置与基本信息共用边框、标题行、caret、间距和 hover/focus 状态。
- 内容区域使用两列布局；在 640px 以下切换为单列，字段 DOM 顺序保持 Server、Tool、超时。
- Tool 加载、无可用 Tool、Tool 已移除和定义变化状态继续显示在测试配置栏目内。

## 5. 自动化验证

- 组件测试覆盖新建默认展开、编辑默认收起、展开操作、字段归属和字段顺序。
- Playwright 生产流程覆盖新建与编辑状态下测试配置的 `aria-expanded` 状态。
- `npm run verify` 已通过：118 个测试文件、860 个测试及 7 条 Playwright 流程全部成功。
