# MCP Inspector 2.0 Independent Release Review

## Conclusion

- Date: 2026-09-02
- Reviewer: independent read-only sub-agent, without the implementation discussion or authority to edit
- Decision: **DO NOT APPROVE the current 2.0 release candidate**
- Findings: **2 Critical, 8 Required, 2 Recommended**

The current artifact checks pass, but their existing assertions do not prove all release criteria. No version, tag, package, or source file was changed by the reviewer.

## Critical

### C1. Inspector session bearer credential crosses URL and browser storage boundaries

Evidence:

- `src/server/main.ts:189-192`
- `src/server/app.ts:220-240`
- `src/client/app/bootstrap-session.ts:3-13`
- `src/client/app/bootstrap-session.test.ts:12-26`

The launch and OAuth return URLs append `?session=<token>`, then the client stores the token in `sessionStorage`. This conflicts with the current rule that secrets do not enter URLs or browser storage. It also exposes the credential to browser history/address surfaces, extensions, and same-page JavaScript.

Recommended remediation: replace the reusable token with a single-use bootstrap ticket that is exchanged for an `HttpOnly`, `SameSite=Strict`, host-only cookie and immediately invalidated. Before implementation, resolve the conflict between the standards' “no secret in URL/browser storage” rule and its instruction to preserve the existing bootstrap/session mechanism.

### C2. Connection URLs can carry query credentials into UI, trace storage, and default exports

Evidence:

- `src/server/connections/connection-service.ts:68-81`
- `src/client/features/connections/ConnectionPanel.tsx:605-617`
- `src/server/connections/observed-fetch.ts:19-23,141-148`
- `src/server/runs/run-service.ts:149-163`
- `src/server/connections/connection-export.ts:173-191`

URLs such as `https://example.test/mcp?access_token=secret` pass validation. The complete URL is displayed, recorded in HTTP observations, and retained in the default Server export. Header redaction does not protect query values.

Recommended remediation: reject credential-shaped query parameters or migrate them to managed Header/secret references; independently sanitize URL display, trace, errors, and export boundaries.

## Required

### R1. Default Server export includes raw business payload without an explicit sensitive-data confirmation

`connection-export.ts` exports Run requests, responses, events, and saved items verbatim. A saved `{ "password": "..." }` value is included. `containsSensitiveToolData` in the manifest does not protect the user before download.

Required decision: default-exclude raw history, or add server-side scanning plus a scope preview and explicit opt-in confirmation. This changes established export semantics and requires product approval.

### R2. The data-bearing migration matrix begins at schema 13, not released 1.0.4/schema 11

`release-migration-matrix.test.ts` creates representative data after migrations 001-013. The existing 11→18 test contains only an empty project. The release gate therefore does not yet prove preservation of actual 1.0.4 Server/Tool/Tab/Run/script/variable data.

Required remediation: add a representative data-bearing 11→18 fixture and retain 13→18 coverage for automated-test data.

### R3. Real authentication fixture matrix lacks pure None and real same-URL isolation

The current `authMode: "none"` fixture sends an API-key Header. Same-URL OAuth/Bearer isolation is covered only with a fake session.

Required remediation: add a pure None fixture that rejects credential headers, plus a same-loopback-URL test using two connection IDs with distinct OAuth/Bearer credentials.

### R4. The 10 MB gate begins after full server and browser JSON parsing

The Viewer bounds React tree rendering, but the real Run route still parses and serializes the complete payload and the browser executes `response.json()` on the main thread. The component timing test begins after the 10 MB object already exists.

Required remediation: introduce a server-side summary/preview endpoint or Worker/streaming decode path, then benchmark from a real 10 MB MCP response until the result pane is interactive.

### R5. Package allowlist accepts arbitrary files below `bin/` and `dist/`

`validatePublishedFiles` currently accepts examples such as `dist/credentials.txt` and `bin/debug-dump`.

Required remediation: define exact runtime entry and hashed asset patterns, exact server chunk patterns, and migration patterns; reject credential/dump/dotfile variants with regression tests.

### R6. English production smoke does not cover the core debug journey and some strings remain hard-coded

The English E2E stops at the Server page and theme switch. It does not connect, open a Tool, edit/execute, and inspect a result. `ArrayObjectEditor.tsx` contains hard-coded `Form`/`Raw JSON`, and Tool folder overlays contain hard-coded eyebrow text.

Required remediation: extend the real English fixture through the core journey and move all product strings into paired locale resources.

### R7. Theme/a11y gate lacks screenshot, contrast, or automated accessibility evidence

The current E2E verifies only `data-color-mode`. There is no screenshot comparison, axe/pa11y/Lighthouse gate, or equivalent contrast evidence.

Required remediation: add stable critical-page coverage for zh/en × light/dark, automated accessibility/contrast checks, and manual review of the highest-risk pages.

### R8. Some Tabs, Dialogs, and Menus do not meet the mandatory keyboard/focus baseline

- Array-object Form/Raw tabs lack roving `tabindex`, Arrow/Home/End, `aria-controls`, and matching tab panels.
- Tool-folder menu lacks Arrow navigation and reliable Escape focus return.
- Three ToolTree modal implementations bypass the shared Dialog, lack a focus trap, and do not reliably return focus after close.

Required remediation: reuse shared Tabs/Dialog/Menu behavior and cover keyboard navigation, focus trap, Escape, outside close, and focus restoration.

## Recommended

1. Extend the 1,000 Tool check from bounded DOM/search latency to continuous-scroll frame or long-task measurements.
2. Build one immutable `.tgz`, validate/hash/smoke that exact tarball, and publish it. The current publish command can run `prepack` again after the dry-run check.

## Positive observations

- Released migrations 001-011 are unchanged, and migration application remains ordered and transactional.
- Current build artifacts pass the existing gate: initial JS 149.95 KiB gzip, CSS 49.75 KiB gzip, 18 bundled migrations, and 31 package files.
- The independent reviewer found no additional unreported mutation, publish action, or released-migration rewrite.
